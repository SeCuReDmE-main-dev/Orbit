# A bounded Codex task for Orbit Companion

This is a task-brief worksheet derived from [OpenAI Academy's Get Started with Codex, lesson 1.4](https://academy.openai.com/learn/get-started-with-codex-zy8qn/lessons). It is guidance for future work, not an implemented feature or a passing test.

Before using it, read `HUMAN.md`, inspect the current branch and working tree, and identify the behavior in the actual code. Keep Sanity Studio, the Chrome side panel, the local broker and the physics lab distinct unless the task requires a specific boundary between them.

| Field | Fill this in before editing |
|---|---|
| Goal | One observable behavior to add or correct, with the user-facing reason. |
| Context pointers | The visible screen or failing behavior and the files, commands, errors or tests to inspect first. |
| Constraints | Existing behavior to preserve; allowed directories; privacy, browser permissions and external-service boundaries. |
| Done when | The behavior can be observed and the named targeted checks pass; remaining external or manual validation is listed. |

For a small, understood change, inspect and implement directly. For an ambiguous change across unfamiliar components or with meaningful security or regression risk, review a short plan first. If the implementation begins unrelated redesign or dependency changes, stop that part, restate the boundary and continue with the original outcome.

Record the pre-change test/build result when relevant. Afterward, show the diff and the exact commands and outcomes. A local fixture or a visible UI state does not establish a live Sanity, Exa, provider or WebMCP integration.
