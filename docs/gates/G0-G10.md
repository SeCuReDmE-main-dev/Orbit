# Gate specifications

## G0 — Repository and runtime truth

Pass when repository path, remote, branch, HEAD, staged/unstaged/untracked state, OS, shell and applicable instructions are captured. In a repository with no commit, record `HEAD_UNBORN` rather than inventing a revision. Evidence: command receipt and instruction file digests.

Fail on ambiguous checkout, conflicting instructions or unowned overlapping changes. Use `BLOCKED_EXTERNAL` when the repository or required runtime is unavailable.

## G1 — Mission boundary

Pass when objective, single transformed output, target user, measurable success, non-goals and stop conditions exist. Every ActionCard must map to one acceptance criterion and have explicit dependencies.

Fail on open-ended goals, hidden side effects, unbounded iteration or action cards unrelated to the objective.

## G2 — Contract and schema compatibility

Pass when input/output data validates, provider/knowledge/mission contracts use supported versions, and CCPPackage is `1.x` or has a tested explicit migration. Contract tests must include invalid inputs.

Fail on unknown major versions, permissive parsing that discards authority fields, or runtime types that drift from shared contracts.

## G3 — Authority and identity

Pass when actor, capability, target, required authority, granted authority and expiry are verified. External actions require a receipt bound to card ID, request digest and target.

Fail on ambient credentials, inherited approval, approval replay, target substitution, or capability-mode mismatch. Missing account/MFA/approval is `BLOCKED_EXTERNAL`.

## G4 — Knowledge provenance

Pass when every material claim has an allowed source, URI, content digest, capture time, trust class and freshness decision. Untrusted content is isolated from control instructions.

Fail when retrieved content can set authority or tools, sources cannot be distinguished from inference, or private content exceeds the mission's data scope. Unavailable approved sources are `BLOCKED_EXTERNAL`.

## G5 — Budget enforcement

Pass when the mission ceilings are exactly 9 model calls, 30 minutes, 40 candidate records, 18 claims and depth 2. Each ActionCard also has exact limits for wall time, provider calls, input/output tokens, knowledge reads, bytes stored, retries and spend. Preflight rejects impossible actions and postflight records actual use.

Fail when any dimension is missing, counters can reset during retry, or over-budget work continues. Current spend limit is exactly zero US cents.

## G6 — Continuity and retention

Pass when CCPPackage identity, mission ID, version, digest chain and retention are valid; secrets are absent; resume reproduces card states and open questions.

Fail on tampering, cross-mission import, unknown major version, secret material or expired retention. Missing migration implementation is `BLOCKED_EXTERNAL`.

## G7 — Security controls

Pass when targeted tests show schema rejection, least capability, authority denial, approval anti-replay, budget abort, prompt-injection isolation, secret exclusion and CCP integrity rejection.

Fail when any high/critical threat lacks a preventive control and observable evidence. Provider-specific controls remain `BLOCKED_EXTERNAL` until a provider is chosen.

## G8 — Verification and benchmark

Pass when targeted unit/integration tests pass and the benchmark protocol meets every mandatory safety threshold. Record exact commands, versions, inputs, repetitions and failures.

Fail on weakened assertions, omitted failing fixtures or claims based on partial runs. Infrastructure unavailable after bounded attempts is `BLOCKED_EXTERNAL`.

## G9 — Evidence and release readiness

Pass when diff review shows only intended files, secret scan passes, contracts and documentation agree, build artifacts are reproducible and all residual risks have owners.

Fail on undocumented behavior, unsupported success claims, missing licenses/attribution, stale evidence or unowned critical risk.

## G10 — Human final acceptance

Pass only when a named human reviews the exact artifact digest, target, public/private scope, cost and rollback, then authorizes that single release action at action time.

Fail on broad standing permission, changed artifacts, unresolved BLOCKED_EXTERNAL dependencies or an expired receipt. No software component may self-approve G10.
